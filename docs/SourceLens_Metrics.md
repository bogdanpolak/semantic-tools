# SourceLens Metrics

This document describes the metrics currently produced by SourceLens and candidate metrics that can be added.

## Current metrics (implemented)

- **Method identity**: `UnitName`, `ClassName`, `MethodName` — captured for each method (see SourceLens.Types).
- **Visibility**: `IsPublic` — derived from interface/type declarations via PublicMethod extraction.
- **BodyLines**: number of executable body lines inside the method. Calculated from the method `ntStatements` node span.
- **CyclomaticComplexity**: base complexity `1` plus AST decision points such as `if`, loops, `case` branches, and `except` branches.
- **TestInvocationCount**: heuristic count of method invocations found in parsed test-project ASTs.
- **Parse failures**: files that failed to parse are surfaced in the analysis result.

## How the metrics are computed (notes)
- `BodyLines` uses the `ntStatements` child node's `Line` and `EndLine` to count body lines.
- `CyclomaticComplexity` traverses the method AST and increments for `ntIf`, `ntFor`, `ntWhile`, `ntRepeat`, `ntCaseLabel`, `ntCaseElse`, and exception branches.
- `TestInvocationCount` currently parses test-project `.pas` files with DelphiAST and counts resolved call targets. It handles direct function calls, class-qualified calls such as `TGame.Create(...)`, and simple typed receivers such as `FGame.MovePlayerBy(...)`. It still favors a small implementation over full semantic resolution, so chained receivers and more advanced dispatch patterns can be undercounted.

## Next metric (not yet implemented)

Metric description:

- **MaxIndentationLevel**: the maximum 0-based column index where an executable statement begins inside the method body. Computed by scanning AST nodes' `Line` and `Col` values for executable node types.

Implementation details:

- `MaxIndentationLevel` uses an AST-driven approach: a set of node types are considered "executable"; the analyzer records the first column (`Col`) of each executable node and returns the maximum observed column per method.
    - Assumptions: Source files use spaces for indentation (tabs are not supported). The `TSyntaxNode.Col` metadata from DelphiAST is 1-based and counts characters from the start of the line
    - The implementation should ideally ignore continuation lines or normalize them to avoid skewing the metric.


## Candidate additional metrics

- **NPath / Nested block depth**: measure number of distinct execution paths or nesting depth beyond indentation (AST-based nested node counting).
- **Number of statements**: raw count of statement nodes (complements `BodyLines`).
- **Average statement length**: characters per statement, highlighting very long statements.
- **Parameter count and local variable count**: method signature metrics to detect large interfaces or heavy local state.
- **Comment density**: ratio of comment lines to body lines per method.
- **Test coverage hints**: correlate method name/namespace with test files (requires test discovery / heuristics) to report methods lacking tests.
- **Maintainability index**: composite metric combining size, complexity, and comment density.
- **Token-based indentation handling**: improve `MaxIndentationLevel` to normalize tabs and ignore continuation lines more robustly via token inspection.
- **File / unit level aggregates**: totals and averages per unit/class (sum/mean of BodyLines, complexity, etc.).
- **Export formats**: JSON/CSV output for integration with dashboards or CI.

## Implementation notes & tradeoffs
- AST-driven metrics are robust where `Line`/`Col` metadata is present (fast, no rescanning). When metadata is missing or includes come from `.inc` files, the analyzer must ensure correct filename mapping or fallback to scanning the physical source text.
- Some metrics (cyclomatic, NPath) are best implemented via AST traversal; others (comment density, average statement length) require source-text access.
- Tab handling: current code assumes spaces; adding normalization is straightforward but must be consistent for report consumers.
- Backwards compatibility: keep `BodyLines`-first sort order in `TReportPrinter` while exposing new fields.
